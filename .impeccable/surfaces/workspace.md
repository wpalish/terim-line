### Task sequence and evidence hierarchy

The default Sessions collection places its task heading and description before Start/Refresh and the searchable native table. This list viewport is documented from source; it is not included in the current five-capture review packet.

Active detail reads menu/version/language/owner, state, server start/deadline, authored prompt/choices and invalid-attempt count before Refresh, the synchronization-based countdown, native digit form, keypad and explicit cancel/timeout controls. The keypad is three columns, at most 360px wide, with zero centered on its final row. Only the active session's owner sees event controls. The countdown is `role="timer"` / `aria-live="off"`; it never saves an event by itself. A refusal keeps the current screen and focuses the shared polite status notice. A successful action renders the returned saved session and focuses its heading.

A native numbered list preserves the supplied event-array order. Each event keeps type/time, actor, input, resulting state, invalid count, optional outcome/label and request key together. The native **Точное меню этой сессии** disclosure follows, then the publication digest. Terminal detail retains version, deadline, invalid count, chronology and snapshot, and states that the outcome is model-only.

The Russian document language remains on digits and interface status/outcome phrases. Authored prompts, selected choice-label spans and saved event labels carry their authored `ru`/`kk` language. The F1 correction isolates the KK label span instead of marking a Russian suffix as KK. Exact text uses text nodes; prompts and saved event labels preserve line breaks.

### Responsive and focus treatment

The inherited shell stacks at 700px and search/table adjustments apply at 600px. Navigation wraps; actions can wrap, while the keypad keeps three equal columns. Headings, event timestamps/keys, disclosure content and digest wrap rather than truncate. The native table owns horizontal scrolling inside a labelled focusable wrapper. Visible focus uses the inherited amber outline, the skip link appears on focus, detail screens focus a temporary heading target, and refusal notices focus the shared status target. These are source-supported mechanisms, not a full assistive-technology audit.
